# Spike: MCP server on mcp-handler 2.2.0

*Fri 10/16. Part of the day-one spike. Feeds ADR 0002.*

## Setup

- `app/mcp/route.ts` serves the public MCP server with `mcp-handler` 2.2.0, `@modelcontextprotocol/server` 2.2.0 and `zod` 4.6.5 (each at least 14 days old) on Next 16.3.6, the version the repo pins. The plan named Next 16.3.8, which was too new under the pin rule when the repo was made.
- One spike tool, `about_corner_office`, read-only with `readOnlyHint: true`. The desk tools join with the engine.
- `scripts/check-mcp.mjs` is the smoke test. It pins the client to the 2026-07-28 protocol with no fallback, lists tools, fails any tool without `readOnlyHint`, and calls each once. It runs in CI as the `mcp` job against a local production build.

## Results

| Client | Where | Protocol | Result |
|---|---|---|---|
| `@modelcontextprotocol/client` 2.2.0, pinned to 2026-07-28 | local and lab.moontaxilab.com | 2026-07-28 | Connected, listed one tool with `readOnlyHint`, call OK |
| `@modelcontextprotocol/sdk` 1.31.0, a 2025-era client | local and lab.moontaxilab.com | 2025-11-25 through the fallback | Connected, listed, call OK |
| GET on `/mcp` | lab.moontaxilab.com | | 405, as the README says for stateless serving |

- Builds cleanly on Next 16.3.6 with Turbopack, as a dynamic route.
- Responses carry `x-robots-tag: noindex, nofollow` like the rest of the site.

## Gotcha

The v2 client defaults to the 2025 protocol. A client must opt in with `versionNegotiation: { mode: "auto" }` or a pin to speak 2026-07-28. Our server handles either, so this only matters for our own tests, which pin.

## Called from Claude

**Pass on claude.ai web, Fri 10/16.** Paula added `https://lab.moontaxilab.com/mcp` as a custom connector with no auth. Asked to use the Corner Office tool, Claude called `about_corner_office` and relayed it accurately, and it noted that the description tool is the only one so far.

**Pass on the Claude iPhone app, Fri 10/16.** The connector carried over from the web with no setup, and the reply shows "Used Corner Office: About Corner Office."

**Both the web and the app asked Paula to allow the tool before calling it.** So `readOnlyHint` does not skip Claude's permission prompt for a custom connector, at least on first use. For the 10/24 meeting, set the connector's tool permission to always allow beforehand, or treat the Allow tap as part of the demo. Whether a read-only tool can skip the prompt by default is worth a later check, not a blocker.
