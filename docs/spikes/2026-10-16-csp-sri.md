# Spike: hash-based CSP with experimental SRI on Turbopack

*Fri 10/16. Part of the day-one spike. Feeds the CSP decision in ADR 0002.*

## Question

Does Next's experimental Subresource Integrity (`experimental.sri`) work with a Turbopack build, or do we need webpack to get a hash-based Content Security Policy without nonces?

## Method

Next 16.3.6 with `experimental: { sri: { algorithm: "sha256" } }`, built once with Turbopack (the default) and once with `next build --webpack`. Each build was served with `next start`, and the HTML of `/` and `/dev/graybox` was checked for `integrity` attributes on script tags and script preloads. The config change was reverted afterward, so nothing ships yet.

## Results

| Build | Page | Script tags | With `integrity` | Script preloads with `integrity` | Inline scripts |
|---|---|---|---|---|---|
| Turbopack | `/` | 7 | 5 | 1 of 1 | 2 |
| Turbopack | `/dev/graybox` | 7 | 5 | 1 of 1 | 2 |
| webpack | `/` | 7 | 5 | 1 of 1 | 2 |
| webpack | `/dev/graybox` | 6 | 5 | 1 of 1 | 2 |

- **Turbopack is enough.** SRI works the same on both bundlers, so there's no reason to switch to webpack.
- **SRI is partial.** Shared framework chunks get hashes, but each page's own chunks do not (on `/` that was two chunks under Turbopack, and the `app/page` chunk under webpack).
- **Every page has two inline scripts**, Next's streamed page data. Integrity attributes cannot cover inline scripts, and their content changes per page and per build.

## What it means

A strict hash-only `script-src` is not reachable with today's SRI. The missing page-chunk hashes and the inline scripts would both be blocked. The two real options:

1. **Nonces.** A strict policy with a fresh nonce per request, set in the proxy. It works, but it forces every page to render dynamically, which costs the static first paint the desk relies on for its 2.0s LCP budget.
2. **Same-origin scripts with strict everything else (recommended).** `script-src 'self' 'unsafe-inline'`, plus `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'self'` and `connect-src` limited to our own origin. Every script we load comes from our own domain, and no third-party script is allowed. The main injection risk in this app is model and email text, which React renders as text, never as HTML, and the guard pipeline screens it first. SRI can still be turned on for the integrity it does add to shared chunks.

**Decision, Fri 10/16.** Paula chose option 2, same-origin scripts with strict other directives. The header lands with the desk UI and is recorded in ADR 0002.

Re-check this when Next marks SRI stable or adds hashes for page chunks and inline scripts.

## Housekeeping

Two `next-server` processes from local test runs outlived `pkill -f "next start"` and kept their ports, which briefly made an earlier run of this test read the wrong build. Local scripts should stop servers by port (`lsof -t -iTCP:<port>`), not by command line.
